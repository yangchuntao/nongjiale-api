## 1. 问题与目标用户

| 角色 | 一期要完成的一件事 |
|------|-------------------|
| 游客 | 发现 → 列表 → 详情 → 登录提交意向 → 我的意向只读 |
| 运营/客服 | 入驻审核、全站房源与资讯、意向跟进、站点配置 |
| 商家 | 入驻通过后维护**自己名下**门店/套餐信息（结算不做） |

成功表现：游客拿到单号+可拨打配置客服电话；运营能审入驻、跟进意向；商家能改自家店资料且看不到他人数据。

## 2. 门户侧（锁定，对齐印程公开主路径）

### 做

1. 首页：搜 + 地区/热门目的地 + 推荐楼层 + 攻略入口 + 信任条 + 客服电话 + 登录/注册  
2. 地区：省→市（县可选）；种子可先长三角  
3. 列表：筛（下级地区、特色、价格；星级可选）+ 排（综合/价格/销量）+ 卡片字段 + 分页/空态  
4. 详情：图集、地址、`tel:`、套餐说明、须知、交通、周边、评论（一期运营录入或种子只读）、推荐、「立即预订」「在线咨询」  
5. 意向表 + 成功页（单号 + 配置电话；文案写清意向≠已锁房）  
6. 登录/注册（手机号+密码）  
7. 我的意向（只读列表+详情）  
8. 攻略/资讯列表+详情  
9. 页脚静态帮助/关于（可配置）

### 门户明确不做（一期）

在线支付/定金收银台 · 锁房/实时库存 · 积分 · 未登录下单+短信查单 · 问答 · 私人定制 · 专题频道 · 地图 · IM · App · 门票 · 动态码登录 · **游客侧结算**

## 3. 商家端（完整商家端 · 结算后置）— 一期做

第三端（建议工程 `apps/merchant`），与门户、运营管理端分离。

### 3.1 入驻审核

| 规则 | 内容 |
|------|------|
| 入口 | 门户/页脚「商家入驻」→ 提交入驻申请（主体名称、联系人、手机、拟营门店名/地区、说明；证照字段一期可先文本+图片上传位，审核标准运营人工看） |
| 状态 | `待审` → `已通过` / `已驳回`（驳回须填原因；可再提） |
| 通过后 | 运营创建或系统开通**商家账号**，绑定该商家主体；首次登录改密 |
| 谁审 | **仅运营**（客服不可审入驻） |

### 3.2 多店归属

- 一商家主体下可有**多门店（农家乐房源）**  
- 商家账号只能看见/编辑**本主体名下**门店  
- 运营可跨商家查看与代编辑、可调整门店归属  

### 3.3 店信息维护（商家）

商家可改自家门店：

- 基础：名称、地址、电话、简介、图集  
- 套餐/价格档文案、特色标签、交通/须知/周边文案  
- **不可**改：归属商家、全站推荐位权重、站点级配置  

保存策略：资料类字段保存即对后台可见；**对游客可订**仍取决于上架审核通过（§3.4）。

### 3.4 上下架（已拍：B）

**已定 B：** 商家提交上架/下架申请 → 运营通过后对游客生效；驳回须填原因。商家不可绕过审核直接上架。运营可代为上下架。

### 3.5 意向单可见范围（已拍：M1）

**已定 M1：** 商家只读本主体门店下的意向（到店日、人数、状态、备注摘要；联系人手机脱敏）；**不可改状态、不可写跟进**。跟进与改状态仅运营/客服。

### 3.6 结算 / 对账 / 支付

**已拍：后置。** 一期商家端不做结算、对账、提现、分账、收银台。与「不做支付」一致。

## 4. 运营管理端（在 Demo 上加厚）

- 入驻审核队列  
- 全站房源/套餐/标签/推荐位/资讯  
- 意向跟进（待跟进→已确认/已改期/已关闭 + 备注时间线）  
- 商家账号启用/停用、重置密码  
- 上下架申请审核队列（方案 B）  
- 站点配置：站名、主色、客服电话  
- 权限：运营全量；客服 = 意向跟进 + 房源只读（**无**入驻审、无商家账号管理，除非另拍）

## 5. 角色与数据隔离（验收必测）

| 角色 | 能 | 不能 |
|------|----|------|
| 游客 | 门户逛、登录交意向、我的意向只读 | 任何管理端 |
| 商家 | 本主体门店维护、提交上下架申请、只读自家意向 | 他人门店、入驻审、改意向状态、全站配置、结算 |
| 客服 | 意向跟进、房源只读 | 入驻审、改权限、删站 |
| 运营 | 全站 | — |

## 6. 一期明确不做（汇总）
