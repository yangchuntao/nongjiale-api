## 状态与「后端可测?」说明

| 状态 | 含义 |
|------|------|
| 待测 | 未执行（本版默认） |
| PASS / FAIL | 已执行结论 |
| 阻塞 | 依赖未就绪（如开城实现未合入、扬州补数未齐） |
| 不测 | 明确不做或抽检项 |

| 后端可测? | 含义 |
|-----------|------|
| **是** | 契约已落地且 main 有对应接口，可不靠 UI 先 API 验 |
| **部分** | 可读现有接口抽检，或契约未全；UI/文案/计数展示需联调 |
| **否** | 待开城写接口落地或纯 UI 才能完整验（本版开城写路径均为否：路径已定、实现未合） |

**方式：** API / UI / 人工（可组合）。

### HTTP 语义（沿用 MVP-0 + TECH 开城契约）

| 码 | 用途（已定 / TECH） |
|----|---------------------|
| **410** | 下架详情；对不可订店提交意向；**CLOSED 市店** `GET /api/stores/{id}` / `POST /api/booking-intents` → message **「已下架或不可用」** |
| **409** | 开城冲突：未达标开通 `未达标，不能开通：`+缺项（`；` 连接）；已 OPEN 再开 `该市已开通`；已 CLOSED 再关 `该市未开通`；乐观锁 `数据已被修改` |
| **400** | 校验失败；手改 `supplyReady`/`articlesReady` → `供给达标与攻略达标按实时计数自动勾选，不能手改` |
| **401** / **403** / **404** | 未登录 / 无角色或越权 / 资源不存在 |

> **v0.2：** 下表「接口路径」已对齐 TECH；Admin 需 Bearer（OPERATOR/AGENT）。**实现未合入前「后端可测?=否」**，断言以「可观察结果」列为准。

## 前置总览（测服）

| 项 | 要求 |
|----|------|
| 基线 | MVP-0 测服可用；门户/运营/商家三端可达；意向状态机与一期一致 |
| 种子开城 | TECH V4：`yangzhou` / `taizhou` / `nantong` 种子即为 **OPEN**（三项手勾 true），**即使店/攻略计数 < N/M**。做「从零开通 / 未达标禁开」须先 **关城** 或改用其他 CLOSED 市 |
| 扬州补数 | 验收开通前（若已关再开）：扬州市上架可意向店（`ON_SHELF && !test_data`）≥ **5**、关联已发布攻略（`PUBLISHED`）≥ **1**、①④⑤手勾可勾；无对客可见爬取脏数据 |
| 账号 | 运营 Token（`POST /api/admin/auth/login`，沿用种子，Bearer OPERATOR/AGENT）；游客 Token；商家 Token（只读意向抽检） |
| 配置 | 开城单位=地级市；区县仅筛选项，不单独开城；N/M 以详情 `minStores`/`minArticles` 为准（默认 5/1） |

### Checklist 五项（C10 / 开通门禁）

| # | 项 | TECH 字段 | 说明 |
|---|----|-----------|------|
| 1 | 目的地数据齐 | `destinationReady` | **手勾**；省/市（区可选）地理数据完备，可被门户 Chip/筛使用 |
| 2 | 供给达标 | `supplyReady` | **自动**：`storeCount >= minStores`（`ON_SHELF && !test_data`）；**不可手改** |
| 3 | 攻略达标 | `articlesReady` | **自动**：`articleCount >= minArticles`（`PUBLISHED`）；**不可手改** |
| 4 | 客服覆盖已说明 | `supportCovered` | **手勾**；运营确认该市客服覆盖说明已记录 |
| 5 | 测数/脏数据已清理 | `dirtyDataCleared` | **手勾**；确认该市无爬取脏数据对客可见 |

开通条件：①④⑤ 手勾均为真，且 ②③ 实时计数达标。`PATCH .../checklist` 仅可写 `destinationReady` / `supportCovered` / `dirtyDataCleared` + 必填 `version`；体带 `supplyReady`/`articlesReady` → **400**。
