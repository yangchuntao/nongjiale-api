## 1. 问题与目标用户

| 项 | 内容 |
|----|------|
| 用户问题 | 想找农家乐的人，难在一处按地区看清房源、套餐价与须知，并留下可跟进的预订；运营缺少统一房源/内容维护与意向跟进 |
| 目标用户 | 游客（主）；运营/客服（管理端） |
| 一期一件事 | 游客完成「发现 → 列表 → 详情 → 提交预订意向」；运营完成「跟进意向 + 维护房源/资讯」 |
| 成功表现 | 游客看到单号 + 可拨打配置客服电话；运营能改状态、写备注 |

## 2. 建议默认（请老板拍）

与 Demo 已跑通能力对齐、并贴近印程主路径：

| 项 | 建议 | 理由 |
|----|------|------|
| 预订模型 | **意向单 + 客服确认**（不做在线支付/锁房） | 印程本质也是二次确认；首发不做支付风险更低；文案须写清「意向≠已订」 |
| 下单登录 | **须登录**再提交意向（Demo 已验） | 印程可不登录；我们一期用登录保证跟进与防刷，查单走「我的意向」 |
| 查单 | **只读「我的意向」**（登录后）；不做游客短信查单 | 避开短信成本；对照印程「订单查询」用账号列表替代 |
| 内容 | **资讯/攻略列表+详情**（运营可维护） | 照抄印程攻略位；专题/问答/私人定制见「暂不做」 |
| 库与部署 | MySQL · 公网一套 · 站名/主色/电话可配置 | 延续此前工程建议 |
| 认证 | 手机号+密码（弱口令不进正式） | 动态码登录后置 |

**站名 / 主色 / 客服电话正式值：待老板提供。**

## 3. 照抄哪些（一期做）

### 门户信息结构（对齐印程）

1. **首页**：Logo、搜索（农家乐）、热门目的地/地区入口、分省或推荐楼层、攻略入口、信任条、客服电话、登录/注册入口  
2. **地区/目的地**：省→市（县可选）入口；种子可先长三角，结构可扩展  
3. **列表**：面包屑、筛选（下级地区、特色标签、价格区间；星级可选）、排序（综合/价格/销量）、卡片（图、名、地址、起步价、销量或标签）、分页、空态  
4. **详情**：图集、名称地址、公开电话/`tel:`、起步价、房型/套餐表（包吃住说明、平日/节假日价文案字段）、注意事项、交通说明、周边文案、评论区（一期可只读展示运营录入或种子）、侧栏推荐、「立即预订」「在线咨询」  
5. **预订意向表**：入离日期、人数/数量、联系人、手机、备注 → 提交 → 成功页（单号 + 客服电话）；软提示「提交后客服确认，不代表已锁房」  
6. **登录/注册**：手机号+密码  
7. **我的意向（只读列表+详情）**：状态展示；游客不可自助取消（与 Demo 一致，可拍是否开放取消）  
8. **攻略/资讯**：列表+详情（运营维护）  
9. **页脚**：关于/帮助链接位（静态页可配置）

### 管理端（沿用 Demo 能力，按印程字段加厚）

- 登录、工作台  
- 意向跟进（状态：待跟进→已确认/已改期/已关闭 + 备注时间线）  
- 房源 CRUD、上下架、价格档/套餐说明、特色标签、地区归属、推荐位  
- 资讯/攻略维护  
- 运营/客服账号与权限（运营全量；客服跟进+房源只读）  
- 站点配置：站名、主色、客服电话  

## 4. 一期明确不做

| 不做项 | 说明 |
|--------|------|
| 在线支付 / 定金收银台 | 印程有「线上支付/定金」文案；我们一期砍支付，客服电话收款 |
| 锁房 / 实时库存日历 | 公开仅「剩余充足」级；不做可售间数扣减 |
| 积分 / 积分抵现 | 印程强文案；一期整段砍 |
| 未登录下单 + 短信验码查单 | 用登录+我的意向替代 |
| 问答社区 / 私人定制表 / 专题运营频道 | 印程有；一期用资讯覆盖，表单线索后置 |
| 商家自助入驻后台 | 仅「联系电话入驻」静态说明即可 |
| 地图找店 / IM / App / 门票 | 印程地图不可用或未见；一律不做 |
| 动态码登录 | 后置 |

## 5. 业务规则（草案，拍板后冻结）

1. 意向状态：`待跟进` → `已确认` / `已改期` / `已关闭`（仅运营/客服）  
2. 提交须登录；关联 userId；联系人/手机以提交值为准  
3. 幂等：同用户+同房源+同到店日不重复建单  
4. 下架/草稿不可订（详情+提交双拒）  
5. 离店 > 到店；人数 ≥ 1  
6. 咨询留言须登录，进待跟进队列  
7. 游客一期不可自助取消意向（除非老板改「可取消」）  
8. 文案禁止暗示「已付款即订妥」；成功页明确客服确认
