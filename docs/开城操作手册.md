# 开城操作手册

> 面向运营。回答一个具体问题：**怎么把一个全国任意城市开出来。**
> 相关设计：`PRODUCT-MVP-1-开城-范围.md`、`TECH-DESIGN-MVP-1-开城.md`。

---

## 1. 一句话原理

开城 = **地区表里先有这个市** + **运营在后台把它置为「已开通」**。

两件事是分开的：

| 阶段 | 谁来做 | 在哪里做 |
|------|--------|----------|
| 地区表里有这个市 | 运营点一次「同步全国区划」 | 运营端 → 开城/目的地 → 同步全国区划 |
| 把这个市开通 | 运营逐个市开通 | 运营端 → 开城/目的地 → 进入详情 → 开通此市 |

**商户申请数不参与开城判断。** 开城门槛只看「已上架且非测试的门店数」和「已发布攻略数」。

---

## 2. 第一次使用：先同步全国区划

新环境里地区表只有种子数据（江苏省部分城市）。要让全国城市都能开，先做一次同步。

1. 登录运营端。
2. 左侧导航 → **开城/目的地**。
3. 点右上角 **「同步全国区划」**，确认后等待完成。
4. 看到提示「同步完成：共 3243 条，新增 …」即成功。

同步内容与约束：

| 项目 | 说明 |
|------|------|
| 数据量 | 34 个省级、369 个市级、2840 个区县，共 3243 条 |
| 覆盖范围 | 全国省市区三级，含港澳台 |
| 幂等 | 以国家标准行政区划代码为键，重复同步不会产生重复行 |
| 不覆盖开通状态 | 已开通的城市仍是已开通，不会被同步打回未开通 |
| 不覆盖启停 | 你手动停用的地区，同步不会重新启用 |
| 保留原网址标识 | 已有的 `yangzhou` 这类网址标识不变，已发出的链接不会失效 |

**同步只需做一次。** 之后新增城市不用再同步——除非区划本身有变更（撤县设区、新设市等），那种情况需要重新生成数据文件后再同步。

### 直辖市的特殊处理

北京、天津、上海、重庆，以及香港、澳门，在国家标准数据里是「省级 → 区县」两层，**没有市这一级**。
而本平台的开城单位是市。为此同步数据里为它们补了一个市级节点：

| 地区 | 合成的市级节点 | 开城时选它 |
|------|----------------|------------|
| 北京市 | 北京市（110100） | ✅ |
| 天津市 | 天津市（120100） | ✅ |
| 上海市 | 上海市（310100） | ✅ |
| 重庆市 | 重庆市（500100） | ✅ |
| 香港特别行政区 | 香港特别行政区（810100） | ✅ |
| 澳门特别行政区 | 澳门特别行政区（820100） | ✅ |

## 3. 开一个具体城市（以苏州为例）

### 第 1 步：找到这个市

运营端 → 开城/目的地 → 在「市名」搜索框输入 `苏州`。

- 如果**搜不到**：说明还没同步区划，回到第 2 节做一次同步。
- 如果**搜到了**：点该行的「进入详情」。

列表页每行显示：状态（已开通/未开通）、上架可意向店数、攻略数、最近操作时间。

### 第 2 步：看缺什么

进入详情页，页面顶部是两个计数卡片，下面是五项开通检查：

| # | 检查项 | 判定方式 | 你能改吗 |
|---|--------|----------|----------|
| ① | 目的地数据齐 | 手动勾选 | ✅ 可勾 |
| ② | 上架店 ≥ N（默认 5） | 系统实时计数 | ❌ 只读 |
| ③ | 攻略 ≥ M（默认 1） | 系统实时计数 | ❌ 只读 |
| ④ | 客服覆盖说明 | 手动勾选 | ✅ 可勾 |
| ⑤ | 测数/脏数据清理确认 | 手动勾选 | ✅ 可勾 |

页面下方会列出「请完成下列项后再开通」，缺哪项一目了然。

### 第 3 步：补齐供给

**这是最常见的卡点。** 新城市刚同步完，②和③都是 0，必须先把真实供给做出来：

- 让苏州的商家走入驻流程 → 审核通过 → 建门店 → 提交上架 → 运营审核上架。每上架一家店，②加 1。
- 在苏州写（或关联）至少 1 篇已发布攻略，③加 1。

> **注意**：`test_data=true` 的测试门店**不计入**开城门槛。这是刻意的设计——防止用测试数据把城市“顶”到开通线，导致游客看到空城。所以测试店只能验证界面，不能开通。

### 第 4 步：勾选三项并开通

1. 勾选 ①目的地数据齐、④客服覆盖说明、⑤测数/脏数据清理确认。
2. 确认五项全绿、缺项列表为空。
3. 点 **「开通此市」**，二次确认。

开通后立刻生效：门户首页目的地、列表筛选、推荐位都会出现该市。不需要等缓存，开城后会主动失效地区缓存。

### 第 5 步：验证

- 门户首页：目的地 Chip 里出现「苏州」。
- 门户列表：选苏州能看到该市上架门店。
- 运营端列表：苏州状态变为「已开通」。

## 4. 关城

详情页点 **「关闭开通」**，二次确认。

关城的影响：

| 会变 | 不会变 |
|------|--------|
| 门户不再把该市作为可选目的地 | 门店、攻略、意向记录全部保留 |
| 该市门店详情直链返回「已下架或不可用」 | 地区节点仍启用，运营后台仍可编辑 |
| 首页推荐不再展示该市门店 | 历史数据不删除，可随时重新开通 |

## 5. 常见问题

**Q：搜索框搜不到我想要的市，怎么办？**
先确认已点过「同步全国区划」。如果已同步仍搜不到，说明该地区不在国家标准区划里（如开发区、新区），当前不支持单独开城，需要走地区数据补充流程。

**Q：一个市要开很久，能不能批量开？**
当前只能逐个市开通。批量开城是后续能力，取决于「开城粒度」策略的确定。

**Q：开城门槛 N/M 在哪改？**
在站点配置里（键 `open_city.min_stores`、`open_city.min_articles`），默认 5 / 1。开城详情页只显示当前生效值，不能在此页修改。

**Q：为什么苏州我已经有 5 家店了，②还是没达标？**
检查三个条件：门店是否**已上架**（不是草稿或下架）、`test_data` 是否为 false、门店所属地区是否**启用**。三个都满足才计数。

**Q：同步会不会把我的开通记录清掉？**
不会。同步只补名称、排序、经纬度，完全不碰开通状态、启停和上下级关系。这一点有自动化测试守着。

**Q：区划数据从哪来，多久更新一次？**
来自公开的行政区划边界服务，由抓取脚本 `tools/region_sync/fetch_regions.py` 生成，打包在程序里。行政区划每年有少量调整（撤县设区等），建议每年重跑一次脚本更新数据。

## 6. 给工程的说明

### 同步接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/admin/regions/sync` | 同步内置区划数据，返回 `total/inserted/updated/skipped` |
| GET | `/api/admin/regions` | 按父级 adcode 分组的区划树，含开通态与启停 |

两者都需要运营令牌（`OPERATOR` 或 `AGENT`）。

### 更新区划数据

```bash
# 1. 重跑抓取脚本（约 75 秒）
cd tools/region_sync
python fetch_regions.py --out data/regions.csv

# 2. 替换资源文件
cp data/regions.csv ../../src/main/resources/db/region/regions.csv

# 3. 重新打包部署，然后在运营端点一次「同步全国区划」
```

### 数据模型变化（V9）

`region` 表新增：

| 列 | 类型 | 说明 |
|----|------|------|
| `adcode` | VARCHAR(12) | 国家标准行政区划代码，唯一，同步幂等键 |
| `source` | VARCHAR(16) | 数据来源：`SEED` 种子 / `SYNC` 区划同步 |
| `short_name` | VARCHAR(32) | 简称，如「江苏」 |
| `center_lng` / `center_lat` | DECIMAL(10,6) | 政府驻地经纬度 |

`seed_market` 由 NOT NULL 改为可空——全国区划不属于任何种子市场。
