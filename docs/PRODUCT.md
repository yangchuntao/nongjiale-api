## 1. 问题与目标用户

| 项 | 内容 |
|----|------|
| 用户问题 | 想找农家乐的人，难在一处看清房源、价格档和须知并留下可跟进预订；运营缺少统一意向单与房源维护入口 |
| 目标用户 | 游客（主路径）；运营 / 客服（管理端） |
| 本期一件事 | 游客完成「发现 → 详情 → 登录 → 提交意向」；运营完成「登录 → 跟进意向 → 维护房源与内容」 |
| 成功表现 | 游客看到单号 + 可拨打电话；运营能改状态并写备注 |

## 2. 已锁定结论

| 项 | 结论 |
|----|------|
| 预订模型 | **方案 A**：意向单 + 客服跟进；无支付、无锁房、无库存日历 |
| 登录 | **必须登录**才能提交意向 / 咨询留言；未登录点 CTA → 登录 → 回跳原任务 |
| 我的订单 | **一期不做** |
| 成功页 | 单号标识 + 可拨打 **13651814168**（`tel:`，前端走配置 `contactPhone`） |
| 地区 | 可配置；种子先长三角 |
| 可访问日 | **2026-10-20**（发版另批） |
| 参考 | 门户参考百驴公开路径；管理端自拟 |

## 3. 本期范围

### 做

- 门户：首页 / 地区 / 搜索列表、农家乐详情、登录、预订表单、成功页、资讯、在线咨询留言
- CTA 三路：在线预约（表单）/ 电话预订（`tel:`）/ 在线咨询（留言，须登录）
- 管理端：登录、工作台、意向跟进、留言跟进、房源与价格档/上下架、专题资讯、地区与推荐位、运营/客服账号

### 暂不做

支付 / 锁房、我的订单、商家入驻端、景区门票、短信 / IM、地图找店

## 4. 业务规则

1. 意向状态：`待跟进` → `已确认` / `已改期` / `已关闭`（仅运营/客服；接口枚举 `PENDING` / `CONFIRMED` / `RESCHEDULED` / `CLOSED`）
2. 提交须登录；关联 `userId`；联系人/手机可预填账号，以提交值为准
3. 幂等：同登录用户 + 同房源 + 同到店日不重复建单（弱网重试返回已有单）
4. 下架 / 草稿不可订（详情 + 提交双拒）
5. 日期：离店 > 到店；人数 ≥ 1
6. 咨询留言须登录；进待跟进队列
7. 权限：运营 = 房源 + 内容 + 订单 + 账号；客服 = 订单跟进 + 房源只读
8. 游客一期不可自助取消意向

## 5. 验收标准（可测）

| # | 前置 | 操作 | 可观察结果 |
|---|------|------|------------|
| 0 | 未登录 | 点在线预约 | 登录后回到该房源预订表单 |
| 1 | 已登录 + 上架房源 | 提交合法意向 | 成功页：单号 + `tel:13651814168`；库中 `待跟进` 且含 `userId` |
| 1b | 无登录态 | 调提交接口 | 401，不入库 |
| 2 | 已登录 + 同键已有单 | 再提交 / 重试 | 不新增；返回已有单 |
| 3 | 房源下架 | 详情或提交 | 不可订 / 提交拒绝 |
| 4 | 非法日期或 0 人 | 提交 | 字段错误，不入库 |
| 5 | 客服登录 | 跟进确认 + 备注 | 状态已确认；备注时间线可见 |
| 6 | 客服账号 | 改房源 / 改权限 | 无权限，数据不变 |
| 7 | 无结果列表 | 打开列表 | 空态，非报错页 |

咨询留言对齐：未登录点咨询先登录回跳；已登录合法留言入库待跟进（对应测试 T8 / T8b）。

## 6. 文案要点（与设计对齐）

- 主按钮：「提交预订意向」（避免理解成已付款锁房）
- 成功页：「预订意向已提交（单号 xxx）。请联系 13651814168」
- 下架：「该农家乐暂不可预订」
- 三 CTA 文案须区分，勿混用同一动词
