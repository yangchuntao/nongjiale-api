## 1. 用户与主任务（一次一主任务）

| 角色 | 主任务 | 入口 | 完成出口 |
|------|--------|------|----------|
| 游客 | 发现并提交预订意向 | 门户首页 / 地区 / 搜索 | 成功页（单号 + 配置电话） |
| 游客（已登录） | 回看本人意向 | 「我的意向」 | 只读列表 / 详情 |
| 运营 | 入驻审、上下架审、全站内容、站点配置 | 运营管理端 | 审核生效 / 内容已发布 |
| 客服 | 意向跟进 | 运营管理端 | 状态已更新 + 备注 |
| 商家 | 维护自家门店并申请上下架 | 商家端 | 资料已保存 / 申请已提交 |

一期不做：支付、锁房、积分、结算、地图、IM、问答、私人定制、专题频道。

## 2. 门户主流程

1. 发现（首页：搜 + 地区 + 推荐楼层 + 攻略入口 + 信任条 + 客服电话）
2. 地区 / 列表（筛：下级地区、特色、价格；排：综合 / 价格 / 销量）
3. 详情（图集、地址、`tel:`、套餐、须知、交通、周边、评论只读、推荐）
4. CTA：
   - **立即预订** →（未登录则登录并回跳）→ 意向表 → 成功页
   - **电话预订** → `tel:`（`contactPhone` 配置）
   - **在线咨询** →（未登录则登录并回跳）→ 留言表 → 成功提示
5. 成功页：单号 +「请联系」+ 可拨打电话；文案写清**意向 ≠ 已锁房**
6. 我的意向：只读列表 + 详情（不可自助取消）
7. 攻略/资讯：列表 + 详情
8. 商家入驻入口（页脚）：入驻申请表 → 提交成功提示（审核结果后续通知）

## 3. 门户页面清单

| 页面 | 用户看到 | 可操作 | 操作后反馈 | 必做状态 |
|------|----------|--------|------------|----------|
| 首页 | 搜、地区、推荐、攻略入口、信任条、电话 | 进列表/详情/搜索/登录 | 跳转 | 加载 / 空推荐 / 错误可重试 |
| 地区 / 搜索列表 | 卡片：名、起价、特色/销量摘要 | 筛、排、分页、进详情 | 列表刷新 | 加载 / **空态** / 错误 / 窄屏 |
| 详情 | 图集、地址、套餐、须知、交通、周边、评论、推荐；底栏 CTA | 预订 / 电话 / 咨询 | 进表单或先登录；电话拨号 | 加载 / **下架不可订** / 错误 / 窄屏吸底 |
| 登录 / 注册 | 手机号+密码 | 登录、注册、返回 | 成功 → `redirect` | 校验失败 / 错误 |
| 意向表 | 到/离店、人数、联系人、手机（可预填） | 提交、返回 | 成功进成功页；下架/401 明确提示 | 校验 / 提交中防重 / 失败可重试 |
| 成功页 | **单号** + 配置电话可拨 | 回首页、再拨 | — | 无支付入口；无自助取消 |
| 我的意向列表/详情 | 单号、房源、到店、状态 | 只读查看 | — | 空 / 无登录回登录 / 加载 |
| 咨询留言 | 房源上下文 + 留言 + 联系方式 | 提交 | 「留言已提交」+ 电话导向 | 同登录 / 校验 / 防重 |
| 资讯列表/详情 | 标题、正文、相关 | 返回 | — | 加载 / 空 / 404 |
| 商家入驻申请 | 主体名、联系人、手机、拟营店名/地区、说明、证照位 | 提交 | 「已提交，等待审核」 | 校验 / 防重 / 已登录可选预填 |

**门户不做页**：支付收银台、库存日历、问答、专题、地图找店、短信查单。

## 4. 商家端流程与页面（第三端）

**流程**：登录 →（首次改密若要求）→ 门店列表 → 编辑店资料 / 套餐 → 提交上下架申请 → 只读自家意向。

| 页面 | 要点 | 状态 |
|------|------|------|
| 登录 | 商家账号；与运营端入口分离 | 校验 / 错误 / 停用提示 |
| 首次改密 | 运营开通后强制或引导改密 | 校验 / 成功进工作台 |
| 工作台 | 本主体门店数、待审上下架申请数、今日新意向数（只读入口） | 加载 / 空 |
| 门店列表 | 仅本主体；状态：草稿/已上架/已下架/上架待审/下架待审 | 空引导「暂无门店，联系运营」 |
| 门店编辑 | 名称、地址、电话、简介、图集、套餐/价格档、标签、交通/须知/周边 | 校验 / 保存中 / 保存成功；**不可改归属与推荐权重** |
| 上下架申请 | 选上架或下架 + 可选说明 → 提交 | 待审不可重复提交同类；驳回展示原因可再提 |
| 意向列表/详情 | **只读**本店单：到店、人数、状态、备注摘要；手机**脱敏** | 空 / 无改状态按钮 / 无跟进输入 |
| 账号 | 改自己密码 | 校验 |

**商家明确不做**：结算/对账/提现、改意向状态、入驻审他人、全站配置、看他店。

## 5. 运营管理端流程与页面

**流程**：登录 → 工作台 → 入驻审 / 上下架审 / 意向跟进 / 房源与资讯 / 商家账号 / 站点配置。

| 页面 | 要点 | 状态 |
|------|------|------|
| 登录 | 运营 / 客服 | 校验 / 错误 |
| 工作台 | 待跟进意向、待审入驻、待审上下架 | 加载 / 空 |
| 入驻审核队列/详情 | 通过 / 驳回（必填原因）；通过后开通商家账号 | **仅运营**；客服无入口 |
| 上下架审核队列/详情 | 通过后对游客生效；驳回必填原因；可代上下架 | **仅运营**（默认） |
| 意向列表/详情 | 筛状态；`待跟进`→`已确认`/`已改期`/`已关闭`；备注时间线；二次确认 | 空 / 409 刷新 / 客服可写 |
| 留言列表/详情 | 已处理 + 备注 | 同上 |
| 房源列表/编辑 | 全站；运营可改归属与推荐；客服**只读** | 无权限 |
| 资讯/地区/推荐位 | 发布、排序、启用 | 草稿 / 已发布 / 空 |
| 商家账号 | 启用/停用、重置密码 | **仅运营** |
| 站点配置 | 站名、主色、客服电话 | **仅运营**；未定值前占位 |

## 6. 关键状态机（界面反馈）

### 6.1 意向（游客只读 · 运营/客服可写）

`待跟进` → `已确认` / `已改期` / `已关闭`  
商家端仅展示状态文案，无操作。

### 6.2 入驻申请

`待审` → `已通过` / `已驳回`（可再提）  
门户侧：提交成功页；驳回原因在再次进入申请或通知文案中展示（一期可用「我的入驻进度」简页或短信外告知——若产品未开进度页，成功页写清「审核结果将由客服联系」）。

### 6.3 门店上下架（方案 B）

门店对游客可见 = 运营审过的「已上架」。  
商家提交上架/下架申请 → `*待审` → 运营通过/驳回。  
详情页下架：主文案「该农家乐暂不可预订」；预约 CTA disabled；电话仍可用。

## 7. 文案要点

| 场景 | 文案 |
|------|------|
| 主提交按钮 | 「提交预订意向」（避免理解成已付款锁房） |
| 成功页 | 「预订意向已提交（单号 xxx）。客服将与您确认档期，意向不等于已锁房。请联系 {contactPhone}」 |
| 下架 | 「该农家乐暂不可预订」 |
| 留言成功 | 「留言已提交，我们会尽快联系。如需电话请拨 {contactPhone}」 |
| 三 CTA | 「立即预订」「电话预订」「在线咨询」— 动词区分 |
| 我的意向空 | 「暂无意向单，去首页看看农家乐」 |
| 商家上下架待审 | 「已提交，等待运营审核」 |
| 商家意向 | 无「改状态」「写跟进」；脱敏手机如 `138****5678` |
| 入驻成功 | 「入驻申请已提交，审核通过后将开通商家账号」 |

电话展示一律走配置 `contactPhone`；站名/主色走站点配置，未定时用令牌占位。

## 8. 键盘与无障碍

- 表单 Tab 序清晰；主按钮可 Enter  
- 图 / icon 有替代文本  
- 正文与背景对比跟令牌；品牌色未定用中性占位  
- 三端焦点顺序：顶栏 → 主内容 → 主 CTA

## 9. 给前端的实现注意

- 三应用：`apps/portal` · `apps/admin` · `apps/merchant`；登录态与角色不可串端裸跳
- 未登录进预订/咨询/我的意向 → `/login?redirect=…`
- 成功页电话来自 `GET /api/config/public`（或等价）的 `contactPhone`
- 列表卡片、分页、空/错/载复用组件；窄屏详情主 CTA 吸底
- 提交 loading + 防重复；管理端/商家端改关键状态二次确认；409 提示刷新
- 商家端 API 一律带主体隔离；前端不依赖「藏按钮」做安全
- 客服侧栏隐藏：入驻审、上下架审、商家账号、站点配置

## 10. 变更纪律

- 改流程 / 页面 / 文案 → 先改本文档，再同步资深项目经理与前端  
- 发版、改已上线流程前停等批准  
- 对齐产品冻结稿；站名/主色/电话补齐后只改配置与令牌，不改主流程
